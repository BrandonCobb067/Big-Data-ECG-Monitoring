# Big Data ECG Monitoring

Python preparation of two ECG datasets: original Chapman ECG and MIT-BIH Arrhythmia Database. Each dataset is read, cleaned and saved separately. MIT-BIH replaces the restricted IEEE 744-fragment dataset; these are newly generated fragments, not the original 744 records.

## Run

Use Python 3.9 or newer. No third-party packages are needed. Run from the repository root:

```bash
python3 src/main.py test
python3 src/main.py clean-chapman
python3 src/main.py clean-mitbih
```

On Windows use `python` instead of `python3`. Existing cleaned ZIPs are not overwritten. Rename them before repeating cleaning. Logs and summaries are regenerated by the script. The raw ZIPs stay unchanged.

## Data and downloads

Large raw and cleaned ZIPs are kept locally and excluded from Git. A clone includes code, source references, cleaning logs, summaries and empty data folders. The included logs describe the earlier Java preparation run; Python has passed its five checks and sampled numeric comparisons against that output, but has not yet been run over both entire datasets.

Download the original archives on Ubuntu:

```bash
sudo apt install python3 curl
curl -fL --retry 3 -o data/chapman/raw/ECGData.zip https://ndownloader.figshare.com/files/15651326
curl -fL --retry 3 -o data/mitbih/raw/mitbih.zip https://physionet.org/static/published-projects/mitdb/mit-bih-arrhythmia-database-1.0.0.zip
echo '2bf32d649e30c5648ba4a5938a1398f8  data/chapman/raw/ECGData.zip' | md5sum -c -
echo '47b26926927c11bd9174154d367c811afc1b186f650f8a205931ca8c520f0a87  data/mitbih/raw/mitbih.zip' | sha256sum -c -
```

Proceed with cleaning only if both checks report OK. On Windows, use `curl.exe` and `Get-FileHash` with MD5 or SHA256. Allow at least 6 GB free for data and working files.

## Cleaning

Chapman: validate the 12 lead columns and 5,000 samples per recording at 500 Hz; retain microvolt units. Check missing/nonfinite values, interpolate gaps only when at most 1% of a lead is missing, reject exact duplicate waveforms and flag flat leads. Negative values are retained.

MIT-BIH: decode WFDB format 212, select MLII by name, verify channel checksums and initial samples, and convert digital readings to microvolts using header gain and baseline. Apply missing-value, duplicate and flat-lead checks to full recordings. Split accepted recordings into 3,600-sample ten-second fragments at 360 Hz, retaining shorter tails. Raw annotation files remain in the original archive; new fragments are not assigned disease labels.

Previously verified preparation results:

| Dataset | Results |
| --- | --- |
| Chapman | 10,646 checked; 10,632 retained; 14 duplicate waveforms removed; 49 flat leads flagged across 17 retained recordings |
| MIT-BIH | 48 raw recordings; 46 have MLII; 8,280 full fragments plus 46 short tails; records 102 and 104 skipped because they lack MLII |

No values required interpolation in those runs. `cleaning-log.tsv` is a tab-separated processing log automatically written by the script. Each dataset also has `summary.txt` and `source.txt`. Flat leads remain in output for review. Basic checks do not establish clinical validity.

## Data structure and next algorithm

`EcgRecord` holds `record_id`, `sample_rate`, `leads`, `units`, and `samples`. Rows in `samples` represent time; columns represent leads. Fragment filenames retain the source record and starting sample.

Planned experiment: compare unchanged cleaned data, lossless compression, and anti-alias FIR filtering followed by twofold downsampling (500 to 250 Hz for Chapman; 360 to 180 Hz for MIT-BIH). Measure transmitted bytes, processing time, throughput and reconstruction RMSE. Preserve filter state within recordings and account for filter delay. Filtering, benchmarking, classification, Spark and MongoDB integration are not implemented in this preparation script.
